# Orthodox parish website template (blank)

A bilingual (English/Russian) static website template for Orthodox parishes, with one design: navy and gold, Old Standard headings, Church Slavonic accents. It is filled with **sample content** for a fictional parish, "St. Example Orthodox Church" (Храм святого Примера). Every name, address, date, price and image is a placeholder.

The template carries layout and very short placeholder text only. Parish writing (about the faith, visiting, customs, how-tos) is the parish's own content to add later. `npm test` fails if explainer copy, em dashes or QR codes appear.

A parish can set the site up itself in the OrthodoxConnect website builder (edit text fields, switch sections on and off, reorder them), or the Project Orthodox team can do it. Everything lives in plain JSON in `content/`, checked against `schemas/`.

## Pages

| Page | File | Notes |
|---|---|---|
| Home | `pages/home.json` | Hero (next services, address, live badge, feast of the day, buttons, commemoration shortcut), optional Welcome text, cards, rector's message, news, events |
| Our Parish | `parish.json` with `clergy`, `history`, `gallery`, `news` under it | |
| Services | `services.json` with `request-service` and `zapiski` under it | Week and month schedule |
| Livestream & Sermons | `livestream.json` | feature `livestream` |
| Get Involved | `get-involved.json` with `volunteer` under it | feature `getInvolved` |
| Store | `store.json` (product pages are generated) and `cart.json` | feature `store` |
| Donate | `donate.json` | the header button |
| Contact | `contact.json` | map and form |

The menu is built from the pages: `parent` puts a page under another one (in the URL and the dropdown), `order` sorts siblings, `nav.label` / `nav.show` adjust the menu. Add a page anywhere by adding a file.

## Simple settings

| What | Where |
|---|---|
| Parish name, address, phone, email, social links, logo | `content/site.json` |
| Optional parts of the site | `site.features`: `livestream`, `store`, `serviceRequests`, `commemorations`, `getInvolved`, `newsletter`. Off removes the pages, menu items, links and header cart. |
| Church calendar | `site.calendar.style`: `julian`, `revised-julian` or `gregorian` |
| Languages | `site.locales` (one or more; `dir: "rtl"` for right-to-left). Missing text falls back to `site.sourceLocale`. |
| Logo | `site.logo.image`. Any shape works; the header sizes it by height. |
| Sections on a page | The `sections` list in the page file. Move a section to reorder it; `"enabled": false` hides it. |
| Header button, footer | `content/navigation.json` |
| Colors, fonts, spacing | `theme/tokens.json` |

Content files: `services.json` (weekly pattern and dated services), `calendar.json` (feasts), `people.json`, `news.json`, `galleries.json`, `sermons.json`, `giving.json`, `store.json`, `requests.json`, `zapiski.json`, `documents.json`, `links.json`, `ui.json` (interface labels). Search for "Sample" and "Образец" to find what to replace.

Section fields are listed per section type in `schemas/page.schema.json`, generated by `npm run schemas` from `scripts/schemas.mjs`.

## Forms and payments

Every form works in sample mode until it is connected. Each one either posts JSON to its endpoint (`site.forms.contactEndpoint`, `giving.endpoint`, `store.checkout.endpoint`, `requests.endpoint`) or calls a handler the parish adds:

```js
ParishSite.handlers.checkout = (order) => fetch('/api/checkout', { method: 'POST', body: JSON.stringify(order) }).then((r) => r.json());
```

Handlers: `checkout` (store and commemoration notes), `donate`, `contact`, `newsletter`, `serviceRequest`, `ocSignup` and `ocOpen` (OrthodoxConnect). Prices shown on the site are for display; the payment provider must price the order itself.

OrthodoxConnect: `site.orthodoxConnect` holds the parish id, the app URL and the link templates for "Create an event" and "Post a need". Until the parish connects, the events and needs come from `content/integrations/orthodoxconnect.sample.json` and are labeled as samples.

## Build and run

Requires Node 20 or later.

```bash
npm ci
npm run dev     # http://localhost:4321, rebuilds on change
npm run build   # validate content and write the static site to dist/
npm test        # build, links, crosses, copy rules, translation status
```

Upload `dist/` to any static host. Set `SITE_URL=https://your-domain` when building for absolute canonical and sitemap URLs, and `BASE_PATH=/sub/path` if the site is not at the domain root. Serve `404.html` for unknown paths.

Every cross is one shared SVG of the Russian Orthodox eight-pointed cross (`cross()` in `src/components/_primitives.mjs`); `npm run check-crosses` checks that each footrest is higher on the left. Pictograms are Orthodox only.

## Translation (optional)

```bash
export DEEPL_API_KEY=...             # or GOOGLE_TRANSLATE_API_KEY
npm run translate -- --dry-run
npm run translate                    # fill in missing Russian text
npm run translate:check              # status report, no key needed
```

Keys come only from the environment; never commit them. The build works without a key. The script never overwrites text a person wrote or anything marked `"ru_locked": true`. After replacing the sample content by hand, run `node scripts/translate.mjs --seed`.
